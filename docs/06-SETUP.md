## ٢. أول تشغيل — أربع خطوات

### ١) استنساخ المشروع
```bash
git clone https://github.com/Speed3d/sanad-app.git
```
```bash
cd sanad-app
```

### ٢) جلب الحزم
```bash
flutter pub get
```

### ٣) توليد الكود — ⚠️ **إلزامية**
```bash
dart run build_runner build --delete-conflicting-outputs
```

المشروع يعتمد على توليد الكود في ثلاثة مواضع:
- **Drift** → `*.g.dart` لجداول قاعدة البيانات والـ DAOs
- **Riverpod** → `*.g.dart` للـ Providers
- **Freezed** → `*.freezed.dart` لنماذج الـ domain

📌 **الملفات المولَّدة متتبَّعة في المستودع** (٣٣ ملف `.g.dart` و`.freezed.dart`)
— أي أن المشروع **يُبنى بعد الاستنساخ مباشرةً**. لكن شغّل الأمر أعلاه مرة عند
أول إعداد للتأكّد من تطابقها مع إصدار الحزم على جهازك.

⚠️ **الخطوة تصبح إلزامية** بعد أي تعديل على:
- جداول Drift أو الـ DAOs
- الـ Providers المُعلَّمة بـ `@riverpod`
- نماذج Freezed في `domain/models/`

بدونها تظهر أخطاء «Target of URI hasn't been generated» أو تُستعمَل نسخة
قديمة من الكود المولَّد بصمت — وهذا أخطر، لأنه يُبنى ويعمل خطأً.

📌 **ولا تنسَ إيداع الملفات المولَّدة مع تعديلك** — فهي جزء من المستودع.

### ٤) التشغيل
```bash
flutter run -d windows
```

على **VS Code**: اضغط **F5** — الإعداد الافتراضي هو ويندوز.

## ٣. التشغيل على كل منصة

### 🪟 ويندوز — المنصة الهدف
```bash
flutter run -d windows
```
قاعدة البيانات ملف حقيقي:
`C:\Users\<اسمك>\Documents\sales_management_db.sqlite`

مع ملفَّي `-wal` و`-shm` (وضع WAL). **الثلاثة معاً** هي قاعدة بياناتك — انسخها
كلها عند النقل.

### 🍎 ماك
```bash
flutter run -d macos
```
⚠️ **لم يُختبَر بعد.** مجلد `macos/` غير موجود في المشروع حالياً — أنشئه أولاً:
```bash
flutter create --platforms=macos .
```
قاعدة البيانات ستكون في `~/Documents/`.

### 🌐 الويب — للفحص فقط
```bash
flutter run -d chrome --web-port=5000 --web-hostname=localhost
```

⚠️ **لا تحذف `--web-port` أبداً.** تخزين المتصفح (OPFS/IndexedDB) مرتبط
بـ«الأصل» = `المضيف:المنفذ`، و`flutter run` يختار منفذاً عشوائياً بدونه — فكل
تشغيل يصير أصلاً جديداً بقاعدة بيانات فارغة وتضيع كل البيانات.

**قيود الويب:**
- النسخ الاحتياطي **معطَّل كلياً**
- قاعدة بيانات المتصفح **منفصلة تماماً** عن قاعدة ويندوز

## ٥. بناء نسخة الإنتاج

### ويندوز
```bash
flutter build windows --release
```
الناتج: `build\windows\x64\runner\Release\`
انسخ **المجلد كاملاً** (الـ `.exe` وحده لا يعمل — يحتاج مكتبات DLL بجانبه).

### الويب
```bash
flutter build web --release
```
الناتج في `build/web/`.

⚠️ **الخادم يجب أن يُرسل ترويسات العزل** وإلا تراجع Drift إلى قاعدة بيانات
مؤقّتة في الذاكرة وضاعت البيانات:
```
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```
المشروع يحوي `web/coi-serviceworker.js` كحلٍّ بديل للاستضافات التي لا تسمح
بضبط الترويسات.

## ٦. أول استخدام للبرنامج

1. **شاشة الإعداد الأول** — اسم الشركة · سعر الصرف · حساب `super_admin`
2. **أنشئ سنة مالية** — السنوات المالية ← ➕
3. **أنشئ خزينة أو أكثر** — الخزائن ← ➕
4. **ابدأ بسند قبض** لإدخال رأس المال

> 💡 عند الإقلاع يطبع البرنامج في الطرفية:
> `[التخزين] ✅ البيانات محفوظة — آخر إقلاع مسجَّل: ...`
> إن ظهر «قاعدة بيانات جديدة» في **كل** تشغيل فالتخزين لا يستمر ← راجع
> [05-LESSONS.md § ع-٠٢](05-LESSONS.md).

## ٧. نقل البيانات بين الأجهزة

**الطريقة الموصى بها — النسخة الاحتياطية المشفَّرة:**
1. على الجهاز الأول: النسخ الاحتياطي ← تصدير (تختار كلمة مرور)
2. انقل ملف `.smbak`
3. على الجهاز الثاني: النسخ الاحتياطي ← استعادة (`super_admin` فقط)

**الطريقة اليدوية (ويندوز → ويندوز):** انسخ الملفات الثلاثة من `Documents`:
`sales_management_db.sqlite` + `-wal` + `-shm`
⚠️ **والبرنامج مغلق** — النسخ أثناء التشغيل قد يُنتج ملفاً غير متّسق.

## ٨. مشاكل شائعة عند الإعداد

| المشكلة | الحلّ |
|---|---|
| `Target of URI hasn't been generated` | عدّلت جدولاً أو Provider ولم تُشغِّل `build_runner` — الخطوة ٣ |
| البرنامج يفتح على المتصفح بدل ويندوز | ويندوز هو أول إعداد في `.vscode/launch.json` — إن غُيِّر الترتيب أعِده |
| البيانات تضيع على الويب في كل تشغيل | نسيت `--web-port=5000` |
| فشل بناء ويندوز | Visual Studio بلا حزمة **Desktop development with C++** |
| تعارض في الملفات المولَّدة | `dart run build_runner build --delete-conflicting-outputs` |
| `flutter pub get` يفشل | تحقّق من الاتصال ومن إصدار Flutter (`flutter doctor`) |
